# Lansy Deck

Дека собирается из готовых слайдов библиотеки: агент импортирует подходящий слайд в пустой файл Figma Slides и заменяет текст в размеченных слотах. Ничего не рисуется с нуля.

Все команды и пути ниже — из папки навыка. Сначала перейди в неё: `cd ~/.claude/skills/lansy-deck` (или туда, куда навык установлен).

## Файлы

| Что | Где |
|---|---|
| Библиотека слайдов — мастер навыка | Figma Design, fileKey `3m8vS0i2okRWSOD3KaPVUX`, 98 компонентов «Тип/№»; ключи в `data/library.json`. Другого шаблона нет: правка слайда — в библиотеке и её публикация |
| Карточки семейств | `families/*.md` |

| Ритм: правила, энергия и фон слайдов | `data/rhythm.json` |

| Образец сториборда | `examples/storyboard.example.json` |

## Запреты

- **Не писать в библиотеку и старый мастер** (`pmTMwjvBBi6UQdm9j48pAh`). Дека собирается только в новом пустом файле Slides. Плагин отклоняет запись в оба файла; обслуживание библиотеки — только с `--allow-library`.
- **Не выдумывать** цифры, факты о продукте, статьи законов и контакты. Нет данных — бери другой слайд или спроси.
- **Факты — только из текста пользователя.** Нужна цифра или утверждение, которых там нет, — спроси, сам не подставляй.
- **Не менять** кегль, начертание, размеры фреймов и цвета. Текст не влезает — сократи.
- Только шрифты Struve и Supermarker, только цвета палитры, только иконки Iconoteka.
- Supermarker не содержит кириллицы. В русской деке акцент Supermarker не ставить.
- Футер и точечная графика остаются инстансами библиотеки: не отсоединять.
- Не менять скрины продукта. Новые картинки — только присланные пользователем.
- Слайд 45 — дубль 42, не брать.

## Процесс

### 0. Вход
Спроси только то, чего нет в запросе:
1. Контент: текст, тезисы, документ.
2. Цель и аудитория.
3. Язык: английский. Русский — только если пользователь прямо попросил.
4. Длина: число слайдов или «сколько нужно».
5. Отрасль для фото: auto, furn, lux или без фото.

Файл для деки не спрашивай — его создаёшь ты (шаг 1).

### 1. Подготовка
Один раз на машине пользователя — установить плагин: Figma Desktop → Plugins → Development → Import plugin from manifest → `bridge/plugin/manifest.json` из папки навыка.

Для каждой деки:
1. Создай пустой файл Figma Slides в команде Datum: там опубликована библиотека. Есть Figma MCP — вызови `whoami` и возьми план с названием Datum, затем `create_new_file` с `editorType: "slides"` и ключом этого плана. Нет Datum в планах или нет MCP — попроси пользователя создать презентацию в Datum и прислать ссылку. fileKey — часть ссылки после `/slides/`. Имя файла — по теме: «Lansy × <клиент> · <тема>»; создаёт пользователь — попроси сразу так назвать. Титульный слайд, который Figma кладёт в новый файл, сборка уберёт сама.
2. Попроси пользователя запустить плагин, простыми словами и со ссылкой: «Открой файл в Figma Desktop и запусти плагин: Plugins → Development → Lansy Deck Bridge». Сервер моста поднимать не нужно: `deck build` и `deck wait` запускают его сами.
3. Сборка сама ждёт плагин до 10 минут. Отдельно дождаться подключения: `node cli/deck.mjs wait --file <fileKey>`. Мост остаётся работать в фоне; остановить — `node cli/deck.mjs stop`.

### 2. Сториборд
1. Нарежь контент на мысли: одна мысль — один слайд. Сгруппируй в 3–6 секций.
2. Для каждой мысли выбери семейство: `node cli/deck.mjs families`, затем `node cli/deck.mjs family <имя>`. Смотри «Когда не брать».
3. Выбери слайд из таблицы вариантов карточки по числу пунктов и энергии.
4. Посмотри слоты и лимиты: `node cli/deck.mjs slide <№>` (английский по умолчанию, `--lang ru` для русского). Напиши тексты сразу под лимит. Как выглядит слайд — открой превью, путь печатает та же команда. В колонках одного слайда пиши тексты одной длины: колонки выровнены по низу и прыгают, если у одной строк больше.
5. Сохрани сториборд в JSON **вне папки навыка**: рядом с ним сборка запишет `<storyboard>.build.json`. Образец — `examples/storyboard.example.json`. Ключи `texts` — имена слотов, набор `#items` — массив элементов. `\n` — перенос строки, `*слова*` — акцент Supermarker на слайдах, где он есть (10, 12, 17, 18, 24, 26). `footer: {"Topic": "…"}` — тема в нижнем левом углу, список тем — `node cli/deck.mjs footers`; необязателен, на обложках 4–6 футера нет.
6. `node cli/deck.mjs check <storyboard.json>`. Исправляй, пока нет ошибок. Предупреждения разбери: незаполненный слот оставит текст шаблона.
7. **Покажи сториборд и дождись «ок».** Формат: `№ | секция | мысль | слайд (№, раскладка) | E | что нужно (фото, иконки)`. Под таблицей — первая строка отчёта `deck check`.

### 3. Сборка и заполнение
```
node cli/deck.mjs build <storyboard.json> --file <fileKey>
```
- Сначала сам прогоняет `deck check` и не собирает сториборд с ошибками.
- Ждёт плагин в файле, затем пишет только в этот файл. Файл должен быть **пустым**: если в нём есть слайды, сборка откажет. Нетронутый титульный слайд Figma убирает сама.
- Импорт: каждый слайд — компонент библиотеки, отсоединённый в обычный слайд. Раскладки текста в библиотеке закреплены — слайд выглядит как в библиотеке.
- Каждая секция — отдельный ряд, слайды в порядке сториборда. Имён у рядов нет: Figma не даёт называть новые ряды.
- Заполнение: тексты по слотам, тема футера из `footer`. Пункты не добавляются и не удаляются.
- id слайдов пишутся в `<storyboard>.build.json`. Упало заполнение или правишь тексты — повтори с `--fill-only`, импорт не повторяется.
- В конце печатает, сколько текстов вставлено, каких слотов не нашёл, отчёт `deck verify` и ссылку на деку.

Переносы `\n`: ширина текстов закреплена, строки ломаются сами. Ставь `\n` только где `deck slide` пишет «стопка», и в коротких заголовках, где разрыв — часть смысла. Иначе ручной перенос плюс автоматический дают висячее слово.

Заметок докладчика Plugin API не даёт: обоснование выбора слайдов — в отчёте (шаг 5).

Если сборку нужно доделать руками скриптом через мост — особенности Figma Slides (проверено вживую):
- Ряды, созданные `createSlideRow` или `setSlideGrid`, не принимают имя.
- Ряд исчезает, как только из него уходит последний слайд.
- `figma.setSlideGrid([[слайды]…])` раскладывает слайды по рядам.
- Имя слайда — это его номер позиции. Опирайся на id.

### 4. Проверка
`deck build` в конце сам печатает отчёт `deck verify`. Отдельно, например после правок в Figma:
```
node cli/deck.mjs verify <storyboard.json> --file <fileKey>
```
- Ошибки (код выхода 1): текст за краем слайда, текст обрезан рамкой, содержимое auto-layout вылезло за рамку дальше, чем в шаблоне, — значит, налезло на соседей. Сократи текст.
- Предупреждения: висячее слово в конце абзаца; ручной `\n` плюс автоматический перенос; строк больше, чем в шаблоне; колонки с разным числом строк; текст в файле отличается от сториборда. Под предупреждением — строки, как их разбила Figma, и знаков в каждой: переписывай под эту ширину.
- Строки считаются на копии текста вне раскладки, база шаблона — замер сразу после импорта (в `build.json`).

Правки — в сториборде, затем `deck build --fill-only`: он заново заполнит и проверит. Не больше двух кругов. Висячие слова и рост строк исправляй переформулировкой, а не `\n`.

Глазами — скриншоты: `node cli/deck.mjs shots <storyboard.json> --file <fileKey> --out <папка>` (файлы `01.png`, `02.png`… по номерам сториборда). Посмотри ритм и общий вид.

### 5. Отчёт
Ссылка на файл, число слайдов, распределение E1/E2/E3, почему выбраны ключевые слайды, где сокращён текст, чего не хватило.

## Ритм (утверждён 2026-10-23)

Энергия и фон каждого слайда — в `data/rhythm.json`, видны в `deck slide` и `deck list`.
- E1 — спокойный, E2 — один акцент, E3 — громкий фон: лайм, зелёный, графит, градиент, фото, коллаж фото.
- Первый слайд — обложка, последний — финал.
- Два E3 подряд нельзя. Больше трёх E1 подряд нельзя.
- Лаймовых фонов не больше 2, тёмных (графит, зелёный, фото) не больше 2.
- Доля E3 — 15–30%. Выход за норму — предупреждение, не ошибка.
- Один шаблон два раза подряд нельзя. Повторять шаблон в деке можно только у разделов.
- Все разделы деки — из одного шаблона.
- Supermarker: в русской деке нельзя, в английской не больше трёх слайдов.

Всё это проверяет `deck check`.

## CLI

| Команда | Что делает |
|---|---|
| `node cli/deck.mjs families` | список семейств |
| `node cli/deck.mjs family <имя>` | карточка семейства |
| `node cli/deck.mjs list [тип]` | слайды со слотами |
| `node cli/deck.mjs slide <№> [--lang ru]` | слоты слайда, лимиты, энергия, фон |
| `node cli/deck.mjs check <storyboard.json> [--json]` | ритм и лимиты сториборда; код выхода 1 при ошибках |
| `node cli/deck.mjs wait --file <key>` | поднять мост и дождаться плагина в файле |
| `node cli/deck.mjs build <storyboard.json> --file <key> [--fill-only]` | собрать деку в пустом файле Slides и проверить |
| `node cli/deck.mjs verify <storyboard.json> --file <key> [--json]` | переполнения, висячие слова, лишние строки; код выхода 1 при ошибках |
| `node cli/deck.mjs shots <storyboard.json> --file <key> --out <папка>` | скриншоты собранных слайдов |
| `node cli/deck.mjs footers` | темы футера |
| `node cli/deck.mjs stop` | остановить мост |
| `node bridge/bridge.mjs status` | подключён ли плагин и к какому файлу |
| `node bridge/bridge.mjs run <script.js>` | выполнить скрипт в открытом файле |

Флаги `run`: `--read-only` — только чтение; `--args '<json>'` или `--args-file <путь>` — константа `ARGS` в скрипте; `--out <папка>` — сохранить `result.files` на диск; `--timeout <мс>`.
